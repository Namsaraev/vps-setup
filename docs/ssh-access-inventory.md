# SSH access release blockers: targeted base inventory

Base: `5b98c4bf196df99f91655c77581588e4a92ab1b4`, verified against GitHub main and a clean local clone before edits. Branch: `fix/ssh-access-release-blockers`. This is not a new full release audit.

1. **Effective key path / Match:** `part2_setup -> configure_pin -> configure_ssh`. At base lines 1330–1347 configure_ssh checks only `$home/.ssh/authorized_keys`. Its `sshd -T` at 1359 has no connection context. The success fast-path at 1383 also lacks an AuthorizedKeysFile prerequisite. A valid key in an unused file therefore permits password disabling.
2. **Listener identity:** `check_ssh_port` at 75–83 uses only `ss -ltn` and a port suffix. Both configure_ssh (1383, 1506) and final_check (1752) accept a foreign TCP listener.
3. **Rollback:** configure_ssh backs up only the main file (1415), replaces main Port (1420), writes the hardening include (1429), then runs aggregate `sshd -t` (1464). Failure returns with changed live files. The atomic writer protects each individual replacement, not the set. The socket file is written later (1477); no aggregate restore exists.
4. **Bind policy:** configure_ssh unconditionally writes the socket override (1473–1489), resetting ListenStream and replacing it with IPv4/IPv6 wildcards. Only afterwards (1491) does it select socket or service mode. Existing restricted addresses, socket drop-ins and explicit sshd ListenAddress port semantics are not checked.
5. **UFW precedence:** configure_ssh calls ensure_ufw_ssh_port (1406) before persistence. That helper (1212–1246) appends `ufw allow` and searches unnumbered status for any matching ALLOW, ignoring earlier DENY/REJECT. configure_ufw reuses it for active UFW. part2_setup already stops before configure_ufw on SSH failure/skip.
6. **Key path safety:** configure_pin reads existing keys (1007, 1123), creates `.ssh` with mkdir -p (1134), writes predictable `authorized_keys.tmp.$$` (1140), then renames and recursively chowns `.ssh` (1173). Parent/target symlinks, ownership boundaries and substitution races are unchecked. authorized_keys_has_key (943) follows a regular-file symlink.

Deferred unchanged: swap F18/F19, modinfo F20, aggregate overrides F21, limits F22, freshness F24, timer cadence F25, effective needrestart F26, shell lifecycle F27, supply-chain pinning, generic locking/transactions, cloud firewall and automated second login. Desired SSH policy remains 5829 / password no / pubkey yes / root no / kbdinteractive no / MaxAuthTries 3.

## Implemented boundaries

- **Key prerequisites:** before fast-path/apply, real `sshd -T -C user=pin,host=<numeric-peer>,addr=<numeric-peer>,laddr=<local-address>,lport=5829 -ddd` supplies effective output. The current SSH connection provides numeric addresses when available; otherwise loopback is only a synthetic context. It is never used to infer safety of connection-dependent Match policies: OpenSSH's own Include-expanded syntax trace permits only User/Group/All Match expressions. Address/Host/LocalAddress/LocalPort and other conditions fail closed even when they do not match the chosen context. Missing/unknown trace format or versions outside OpenSSH 8.9/9.x/10.2 fail closed. The 10.2 Match diagnostic requires its observed `on line N` suffix; the older grammar remains unchanged. Captured Ubuntu 26.04.1 / OpenSSH 10.2p1 evidence and live temporary-config tests are documented in `openssh-10.2-evidence.md`; GitHub Ubuntu 24.04 CI covers 9.x. This deliberately relies on a bounded OpenSSH diagnostic format, not a handwritten config/Include parser. Full support for arbitrary Match policies would require a separately designed connection policy model.
- Exactly one effective AuthorizedKeysFile row is required. `%h`, `%u`, `%%`, absolute paths and home-relative paths are expanded narrowly; unsupported tokens/quoting/wildcards or exclusion of the installed path fail. Public-key authentication must already be enabled in the effective context, and AuthenticationMethods must allow standalone publickey (`any` or `publickey`). Recheck the effective prerequisite after persistence and before UFW writes/restart. This checks configuration prerequisites, not PAM/account expiry, key options, revocation, external network reachability or a second login.
- **Listener:** `ss -ltnp` owners are checked against loaded/active `ssh.service`, its MainPID and `/usr/sbin/sshd` ExecStart, or PID 1 with a loaded/active non-Accept `ssh.socket` triggering ssh.service and the matching systemd Listen endpoint. Process names do not grant success. Every owner of every target-port listener must match. Missing owners are probe failure. Return codes: 0 expected, 1 absent, 2 probe failure, 4 foreign. This is point-in-time systemd/socket evidence, not cryptographic process attestation or a race-free kernel snapshot.
- **Rollback:** immediately before managed persistence, save original bytes, existence, uid/gid, mode and timestamps in an in-memory JSON snapshot. The existing main-file disk backup remains. Atomic writes occur inside an SSH-only boundary; main, include and socket override (only in socket mode) are all persisted before aggregate `sshd -t`. Persistence/validation failure atomically restores prior bytes, uid/gid, mode and mtime, or removes a newly generated file, and verifies each result. Failed rollback names every affected path and is fatal. No reload/restart or UFW mutation occurs on aggregate-validation failure. Snapshots are not crash recovery; this is not a transaction for service restart failures, ACL/xattr restoration, concurrent administrator edits or the whole script.
- **Bind:** query systemd's merged runtime unit evidence. Reject stale manager state and later drop-ins that could override `99-vps-port.conf`. Preserve ordered numeric IPv4/bracketed IPv6 addresses and all other socket properties; change only a single shared source port. Multiple distinct ports, non-TCP entries, unknown addresses/activation modes and ambiguous state fail with an instruction to inspect ssh.socket. In inactive/disabled socket service mode, do not write an override. Probe real sshd with target Port to reject incompatible explicit ListenAddress ports rather than rewriting admin directives. No wildcard is invented.
- **UFW:** first inspect active numbered rules without mutation, before SSH persistence. An earlier potentially conflicting DENY/REJECT/LIMIT, unresolved profile/range or unknown rule format fails closed with its rule number; unrelated numeric port/UDP denies are left alone. An existing unconditional effective SSH ALLOW is a no-op. If no rule is present and no preceding conflict is found, add the narrow port/tcp ALLOW only after SSH aggregate validation, then verify numbered order. No automatic deny deletion/reordering. Inactive-UFW behavior and unrelated policies/rules are unchanged. This checks UFW's numbered user rules, not arbitrary before.rules/raw nftables or cloud firewalls.
- **Key write:** walk all parents with directory descriptors and O_NOFOLLOW; require target-owned non-group/world-writable home/.ssh/key file. Refuse symlinks (including dangling), hard-linked keys and all nonregular key files. Create an unpredictable O_EXCL temp within the anchored .ssh, write/flush/fchown/fchmod/fsync and verify bytes, then recheck target identity/content and parent identity before replace. Permissions remain .ssh 0700 / keys 0600; no recursive chown. Duplicate detection and options/comments parsing still use the existing OpenSSH fingerprint helper. Pre-replace failures preserve old live bytes. Kernel-atomic exclusion of a malicious concurrent rename between the final check and replace is not claimed; anchored descriptors prevent redirecting the write, and post-checks reject a detached parent. Directory fsync/post-replace errors remain errors but may leave completed new bytes.
