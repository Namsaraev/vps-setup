## Single-file guarantee and limits

The narrow embedded Python helper handles generated text and the three existing
snapshot transformations (fstab, Port, managed zshrc). Python 3 is already a
required installed package. POSIX directory descriptors anchor all path
components; symlink parents, symlink targets and other non-regular targets are
refused. Sources are fully read and checked for identity/size changes. A random
exclusive temporary file is created in the anchored target directory. Short
writes, flush, ownership, permissions, fsync, readback, replace and cleanup
failures are propagated. The parent and source are rechecked before replacement.
Unchanged content returns without creating a temporary or changing the inode.

Existing UID/GID and permission bits are retained; new files are mode 0644 and
owned by the executing identity (the configured current user for shell files).
ACLs/xattrs/SELinux labels are not copied; this is a UID/GID/mode contract, not an
extended-metadata preservation claim. Directory fsync and final no-follow
readback follow replacement. Pre-replacement I/O failures leave the old live
file unchanged. A cleanup failure is nonzero and may leave one staged temporary.
An error after replacement is explicitly reported as such; the complete new
file can remain, without rollback.

Staging validation checks full bytes, metadata and idempotent transformations.
The existing aggregate `sshd -t` still runs in its original position after the
SSH main/drop-in replacements and before restart. This is not a new staged SSH
parser, Include/Match analysis, multi-file transaction, or guarantee that an
invalid pre-existing SSH configuration is repaired. A later parser/restart
failure does not restore previously replaced files. Concurrent provisioning is
not serialized; checks detect observed source/parent changes, not all possible
concurrent changes after the final check. Descriptor-relative operations never
follow a substituted target symlink to write its referent.

For managed swap, normalize only rows whose first field is `/swapfile` and third
field is `swap` to one `/swapfile none swap sw 0 0` row. Preserve foreign rows and
comments byte-for-byte; add a separator LF only when needed. A correct existing
row stays in place. Missing/duplicate/wrong rows are repaired even while runtime
swap is already active with the requested size, without swapoff/allocation/
mkswap/swapon. Persistence failure stops real Part 2 with no completion message;
runtime state may already be active and is not rolled back.

## Deliberately unchanged

- F18 runtime swap replacement/recovery and F19 size/fallback semantics: the
  requested runtime creation/replacement contract is preserved.
- F20 probe masking, F21 effective overrides, F23 diagnostic wording and F26
  effective needrestart mode: separate diagnostic/effective-policy work; no
  claim that fragment persistence proves aggregate or runtime state.
- F22 limit values, F24 package freshness, F25 timer runtime scheduling and F27
  shell component/lifecycle validation: outside the requested write-safety fix.
- F13 key-path races, SSH Match/context validation, Include hierarchy, second
  login, rollback timers, cloud firewall and transactional recovery: separate
  access/architecture work.
- `final_check`, `part3_tests`, external downloads/HTTP, CI/GitHub Actions and
  `ask_password` prompt writes: explicitly excluded; diagnostic/external-test
  bundle remains future work (PR #28).

## Verification design

`test_persistence_repeat_bundle.py` uses the real embedded writer against
temporary paths with filesystem fault injection. It covers all twelve fixed
targets, unchanged bytes/metadata before replace, post-replace errors, cleanup,
symlink/FIFO/directory rejection, representative source/parent substitution,
no-rewrite repetition, swap runtime isolation, and real Part 2 propagation.
Existing affected suites now inject faults into staging instead of obsolete
cat/sed/append calls. All system/service/network/account/swap commands remain
stubbed; the top-level provisioning script is never sourced or run.

Final committed-head Linux results and exact SHA are recorded in the PR body
and accompanying verification report, avoiding a self-referential commit SHA
in this file. Pure transformations and unaffected relevant regressions are
also tested locally on Windows; POSIX filesystem guarantees require Linux.
